# Agent Flow

Claude Code와 Codex의 로컬 세션을 한 화면에서 탐색하는 **Rust TUI**입니다. 이미 실행 중인 에이전트의 JSONL 로그를 읽으므로 에이전트를 다시 실행하거나 훅을 설치할 필요가 없습니다.

```sh
cargo run --release
```

설치해서 어디서든 실행하려면:

```sh
cargo install --path . --locked
agent-flow
```

설치 후 `command not found: agent-flow`가 나오면 Cargo 설치 폴더가 PATH에 없는 것입니다. 즉시 실행하려면 `~/.cargo/bin/agent-flow`를 사용하세요. 현재 터미널에서 이름으로 실행하려면 `export PATH="$HOME/.cargo/bin:$PATH"`를 먼저 실행합니다. 이 PATH 설정을 셸 설정 파일에 추가하면 새 터미널에도 적용됩니다.

Rust 1.88 이상, UTF-8 터미널이 필요합니다. macOS에서 실제 로그와 PTY 동작을 검증했습니다. Flow 화면은 145열 이상이면 세 패널을 나란히 표시하고, 95~144열에서는 상세 패널을 아래에 표시합니다. 더 작은 창에서는 `1` / `2` / `3`으로 패널을 전환합니다.

## 느린 세션 찾기

시작 화면은 **Dashboard**입니다. 기본으로 **최근 24시간에 활동한 세션**을 표시하고, 각 에이전트의 가장 느린 종료 턴 순서로 정렬합니다. `d`로 Dashboard와 기존 Flow 탐색을 전환할 수 있습니다. Flow에서 바로 시작하려면 `agent-flow --flow`를 사용하세요.

```text
1 SESSIONS                            2 TURNS · ended by duration
▸ Fix payment retry boundary          ▸ #01  2m 00s  ENDED · timestamps
  Total 3m 10s  Turn 2m 00s              결제 재시도 조사 1: 테스트로 원인 확인
  exec_command 1m 45s · Open 1m 35s      x exec_command 1m 45s
  Last 4s ago
```

- `w`: 마지막 활동 범위를 **24시간 → 7일 → 전체(All)** 순으로 바꿉니다. 현재 범위는 상단 `Activity`에 표시합니다. 세션 생성일이나 파일 수정일 대신 로그의 마지막 활동 시각을 사용하므로, 오래전에 시작해서 오늘 다시 사용한 세션도 표시됩니다.
- `o`: 선택한 활동 범위 안에서 가장 느린 종료 턴 → 누적 종료 턴 시간 → 가장 느린 도구 → 미완료 턴 경과 시간 순으로 정렬 기준을 바꿉니다.
- `Tab` 또는 `1` / `2`: 세션 목록과 선택한 세션의 턴 목록을 이동합니다. 턴 목록은 종료된 턴의 소요 시간 내림차순이며 미완료·시간 미상 턴은 뒤에 표시합니다.
- `Enter`: 세션의 가장 느린 종료 턴 또는 턴 목록에서 선택한 턴의 시작 기록을 Flow에서 엽니다. 미완료 시간 정렬에서는 미완료 턴을 엽니다. 종료 턴이 없으면 남아 있는 미완료 턴 또는 경계 기록을 엽니다.
- `x`: 세션 또는 선택한 턴에서 가장 긴 **호출 → 결과** 구간을 엽니다. 이 시간은 비동기 명령·에이전트 전체 작업 시간이 아닐 수 있습니다.
- `/`, `p`, `a`: 세션/작업 폴더 검색, 제공자, 최근 작업 중인 세션 필터. 직접 이동할 때는 해당 이벤트가 보이도록 Flow의 도구·오류·검색 필터를 해제하고 Follow를 끕니다.

각 세션의 `Last 5m ago`, `Last 3d ago`는 마지막 활동 이후 경과 시간입니다. 시각이 없는 세션은 All에서만 표시하고 `Last activity unknown`으로 안내합니다. All도 현재 읽어 들인 로그 범위에 한정됩니다. 활동 범위는 Dashboard의 세션 목록에만 적용하며, 세션 내부의 보관된 턴이나 Flow·Parallel의 탐색 범위를 줄이지 않습니다.

새 로그나 기간 전환으로 순위가 달라져도 목록에 남아 있는 세션과 턴의 선택을 유지합니다. 활동 범위를 벗어난 세션은 다음 갱신 때 목록에서 빠지며, 새 활동이 기록되면 다시 나타납니다. Dashboard는 125열 이상에서 두 목록을 나란히, 95~124열의 충분히 높은 창에서는 위아래로, 작은 창에서는 현재 목록만 표시합니다.

**시간의 의미와 범위**

`Total`은 현재 보관된 이벤트에서 시간을 확인할 수 있는 종료 턴(중단 포함)의 누적 경과 시간입니다. 턴 사이의 사용자 입력 대기와 아직 미완료인 턴은 제외하며, 겹치는 턴 구간은 한 번만 셉니다. 턴 안의 승인 대기 등은 포함될 수 있습니다. `Turn`은 그중 가장 긴 턴, `Tool`은 가장 긴 호출 → 결과 구간, `Open`은 시작 시각이 알려진 미완료 턴의 경과 시간입니다. Open은 프로세스가 실제 실행 중이라는 뜻이 아닙니다.

Codex의 시작·완료·중단 기록과 Claude의 사용자 요청·최종 응답 또는 `turn_duration`을 연결합니다. 시작·종료 시각이 있으면 `timestamps`, 시작 기록이 없고 Claude의 명시적인 `durationMs`만 있으면 `reported`로 표시합니다. Claude의 최종 응답 뒤에 별도 소요 시간 기록이 와도 같은 턴을 두 번 세지 않습니다. 시각이 없거나 역전된 구간은 `—`로 표시합니다.

부모와 자식은 각각 별도 행이며 시간을 합산하지 않습니다. 도구들의 시간도 턴 시간에 더하지 않고, 로그 사이의 공백을 LLM 추론 시간으로 단정하지 않습니다. 순위는 **현재 읽은 로그와 보관된 이벤트 범위**에 한정됩니다. 오래된 이벤트가 제거되었거나 로딩 중이거나 시간 근거가 부족하면 `*`가 붙습니다. 전체 세션의 누적 실행 시간으로 해석하지 마세요. 더 넓은 이력을 보려면 `--max-sessions`와 `--max-events`를 늘릴 수 있습니다.

## 에이전트 상세와 병렬 흐름

Flow의 기본 화면은 **Agent Detail**입니다. 선택한 에이전트 자신의 요청·도구·응답만 시간순으로 표시하고, 상단에는 부모 경로, 작업 설명, 상태와 직접 하위 에이전트 수를 보여줍니다. 형제 에이전트의 이벤트가 본문에 섞이지 않습니다. 생성·메시지 이벤트에는 연결된 에이전트 이름과 실제 지시 내용을 표시하며, `Enter`로 연결된 에이전트를 열 수 있습니다. `s`를 누르면 기존의 하위 에이전트 포함 통합 목록으로 전환합니다.

Dashboard 또는 Flow에서 `v`를 누르면 **Parallel** 화면을 엽니다. 같은 루트에 속한 부모·형제·하위 에이전트를 각각 독립된 열로 보여줍니다. 다른 세션은 포함하지 않으며, 에이전트 검색·제공자·활동 필터와 무관하게 해당 가족 전체를 표시합니다.

```text
root                         reviewer                     tests
작업 지시와 최종 조정        재시도 조건 검토             통합 테스트 실행
spawn_agent → reviewer       exec_command ERROR           exec_command RETURN
spawn_agent → tests          send_message → root          send_message → root
apply_patch                  Turn completed               Turn completed
```

- `h` / `l`, `←` / `→`, `Tab` / `Shift-Tab`: 에이전트 열 이동.
- `j` / `k`, 방향키, `g` / `G`: 선택한 열의 이벤트 탐색. 다른 열의 선택과 스크롤은 유지됩니다.
- `f`: 선택한 열만 최신 이벤트를 따라갑니다. 직접 이벤트를 이동하면 그 열의 Follow만 꺼집니다.
- `Enter` 또는 `v`: 선택한 이벤트를 그대로 Agent Detail에서 엽니다. `3`은 바로 입력·결과 상세를 엽니다.
- `/`, `t`, `e`: 모든 열에 이벤트 검색·도구·오류 필터를 적용합니다.
- `b`: 부모 에이전트 열로 이동. `d`: Dashboard 전환.

각 열은 독립된 이벤트 목록이며 **같은 행이 같은 시각을 뜻하지 않습니다**. 실제 이벤트 시각과 호출 → 결과 소요 시간을 확인하세요. 관측되지 않은 인과관계나 LLM 추론 시간을 그리지 않습니다. 한 화면에는 너비에 따라 최대 세 열을 표시하고, 좁은 화면에서는 선택한 열로 전환합니다. 새 로그나 순위 변경에도 열 순서와 에이전트별 선택을 유지합니다.

샘플의 `reviewer`와 `tests`는 같은 부모 아래에서 병렬로 작업합니다.

```sh
agent-flow --demo --parallel
agent-flow --demo --parallel --render 160x38
```

## 무엇을 볼 수 있나요?

```text
 AGENTS                       FLOW                             INSPECT
 ▾ 2 sub · 결제 오류 [Codex]   ◆ 사용자 요청                    exec_command
 └─ reviewer [READY]          ├ exec_command → 결과             INPUT
 ▾ 1 sub · 접근성 [Claude]     ╞ spawn_agent → reviewer            { "cmd": "cargo test" }
 └─ tests [WORKING]            │  ├ exec_command → ERROR         RESULT
                              │  ↔ send_message → 부모          실패한 테스트와 출력
                              ├ apply_patch → 결과
                              └ exec_command → WAIT
```

- **에이전트 트리**: Claude/Codex, 부모·자식 관계, 작업 설명, 상태, 마지막 활동 시점. `Main ~20.0k/200.0k 90% free`처럼 각 에이전트의 현재 컨텍스트 사용량 / 한도와 남은 비율을 표시합니다. 다음 줄의 `351 ev`는 보관 중인 이벤트 수입니다.
- **접고 펼치기**: 하위 에이전트는 기본으로 접혀 있어 메인 세션을 빠르게 찾을 수 있습니다. Agents 패널(`1`)에서 `z`로 선택한 가지를 접거나 펼치고, `Z`로 모두 접습니다. `▸ 12 sub`는 읽어 들인 전체 하위 에이전트 수입니다. `→`는 펼치기·첫 자식으로 이동, `←`는 접기·부모로 이동합니다. 접힘 상태는 앱 실행 중 새 로그가 들어와도 유지됩니다. 검색·필터 변경이나 연결된 에이전트로 이동할 때는 필요한 경로가 자동으로 펼쳐집니다.
- **접힌 목록의 작업 상태**: 하위에 `WORKING` 에이전트가 있으면 부모 타이틀을 노란색으로 강조하고 `● 2 sub working`처럼 개수를 표시합니다. 읽어 들인 모든 중첩 하위 에이전트를 포함하므로 목록을 접거나 검색으로 가려도 확인할 수 있습니다. 부모 자체의 상태와는 별개이며, 완료되거나 `QUIET`로 바뀌면 표시가 사라집니다. 깜박임 없이 텍스트와 색상으로 표시합니다.
- **흐름**: 기본으로 선택한 에이전트의 요청, 응답, 도구 호출, 반환값, 에이전트 생성·메시지를 시간순으로 연결합니다. `v`로 에이전트별 열을 나란히 보고, `s`로 하위 에이전트 포함 통합 목록을 볼 수 있습니다.
- **상세**: 선택한 이벤트의 입력, 반환값, 기록된 소요 시간, 호출 ID, 세션 ID와 원본 로그 경로. 서브 에이전트 링크에서는 `Enter`로 그 에이전트에 들어갑니다.
- **실시간 추적**: 기본 1초 간격으로 새 파일과 추가된 줄을 읽습니다. 로그 읽기는 별도 스레드에서 수행합니다. 같은 세션을 탐색 중에는 선택한 이벤트를 유지하고, `f`를 켜면 최신 이벤트를 따라갑니다. Agents에서 다른 세션으로 이동하거나 이전 세션으로 돌아오면 현재 필터에 맞는 최신 FLOW 이벤트를 선택합니다. 이때 Follow 설정은 유지됩니다.
- **검색·필터**: 세션/작업 폴더 검색, 이벤트 입력·결과 검색, 도구만 보기, 오류만 보기, 제공자별 보기.

안전한 샘플 데이터로 먼저 탐색하려면:

```sh
agent-flow --demo
# 설치 전에는 cargo run -- --demo
```

| 키 | 동작 |
|---|---|
| `d` | Dashboard / Flow 전환 |
| `v` | 에이전트별 Parallel 열 / Agent Detail 전환 |
| Parallel의 `h` `l`, `Tab` / `Shift-Tab` | 에이전트 열 이동 |
| Parallel의 `Enter` / `3` | 선택한 이벤트를 Agent Detail / 입력·결과 상세에서 열기 |
| Dashboard의 `o` / `x` | 시간 정렬 기준 변경 / 가장 긴 도구 호출 열기 |
| Dashboard의 `w` | 마지막 활동 범위: 24시간 → 7일 → 전체 |
| Dashboard의 `Tab`, `1` `2` | 세션 / 턴 목록 이동 |
| `Tab` / `Shift-Tab`, `1` `2` `3` | 에이전트 / 흐름 / 상세 패널 이동 |
| Agents의 `z` / `Z` | 선택한 하위 목록 접기·펼치기 / 전체 접기 |
| Agents의 `h` `l`, `←` `→` | 접기·부모로 이동 / 펼치기·첫 자식으로 이동 |
| `j` `k`, `↑` `↓` | 선택 이동, 상세 내용 스크롤 |
| `g` `G`, `Home` `End` | 처음 / 마지막 |
| `PageUp` / `PageDown` | 10행 이동 |
| `Enter` | 흐름 열기, 상세 보기, 연결된 에이전트로 이동 |
| `b` / `Backspace` | 부모 에이전트로 이동 |
| `[` / `]` | 어느 패널에서든 이전 / 다음 이벤트 |

| `p` | 전체 → Codex → Claude |
| `a` | 전체 / 최근 작업 중인 세션 |

| `?` | 도움말과 로그 접근 경고; `j/k`로 스크롤 |
| `q` / `Ctrl-C` | 종료 |

## 로그 위치와 범위

| 제공자 | 기본 위치 | 해석하는 기록 |
|---|---|---|
| Codex | `$CODEX_HOME/sessions`, 기본 `~/.codex/sessions` | `session_meta`, `turn_context`, `response_item`, `event_msg` |
| Claude Code | `$CLAUDE_CONFIG_DIR/projects`, 기본 `~/.claude/projects` | 세션 JSONL 및 `<session>/subagents/agent-*.jsonl` |

```sh
agent-flow --codex-dir /path/to/codex/sessions \
           --claude-dir /path/to/claude/projects \
           --max-sessions 200 --max-events 3000 --interval 1000
```

기본으로 수정 시각이 최근인 **120개 로그와 확인된 부모 로그**를 읽고, 에이전트당 최근 **1,500개 이벤트**를 보관합니다. 더 오래된 활동을 찾으려면 위 옵션을 늘리세요. 초기 대용량 파일 읽기 진행 상태는 하단 `loading`에 표시합니다.

Codex의 부모 이력 복사본은 `subagent_history_start_ordinal` 경계로 제외합니다. Claude의 자식 로그 경로와 `Agent`/`Task` 결과의 `agentId`를 연결하고, 확인된 생성 기록이 있으면 직접 부모를 교정합니다. 도구 입력과 결과는 `call_id` / `tool_use_id`로 연결합니다. Codex가 기록한 중첩 명령 실행 완료 이벤트도 표시합니다.

## 상태를 읽는 법

이 앱의 상태는 **로그에 남은 활동**을 뜻합니다. OS 프로세스가 실제로 살아 있는지 확인하는 지표는 아닙니다.

- `WORKING`: 열린 턴이며 120초 이내 활동이 기록됨.
- `QUIET`: 열린 턴이지만 120초 넘게 새 활동이 없음. 긴 도구 실행, 승인 대기, 중단 등을 구분할 근거가 부족합니다.
- `READY`: 명시적인 턴 완료가 기록됨. 세션 프로세스 종료라는 뜻은 아닙니다.
- `UNKNOWN`: 턴 상태를 판단할 기록이 없음.
- `WAIT`: 대응하는 도구 결과가 아직 없음. 오래된 로그의 누락·중단도 포함합니다.
- `RETURN`: 결과가 반환됨. 작업의 의미적 성공을 보장하지 않습니다.
- `ERROR`: 명시적 오류 플래그, 실패 상태, 0이 아닌 종료 코드가 기록됨.

## 현재 컨텍스트와 남은 여유

Agents의 `Main` / `Sub`는 해당 에이전트의 **가장 최근 요청에서 기록된 입력 + 출력 토큰**으로 현재 컨텍스트 크기를 추정합니다. 예를 들어 `Main ~20.0k/200.0k 90% free`는 약 20,000토큰을 사용했고 200,000토큰 한도에서 약 90%가 남았다는 뜻입니다. 여러 요청의 입력을 계속 더한 누적 소비량은 화면에 표시하지 않습니다. `1k = 1,000`, `1M = 1,000,000`입니다.

- 메인과 서브 에이전트의 컨텍스트는 각각 표시합니다. 하위 흐름을 함께 보더라도 부모에 자식의 사용량을 더하지 않습니다.
- `~`는 마지막 요청을 기준으로 한 추정치입니다. 그 이후 추가된 사용자 메시지나 도구 결과는 다음 사용량 기록이 남기 전까지 반영되지 않습니다. 구독 한도나 요금 사용률을 뜻하지 않으며, 자동 압축은 표시된 컨텍스트 한도에 도달하기 전에 발생할 수 있습니다.
- Codex는 `last_token_usage` 또는 요청별 `usage`에서 사용량을, `model_context_window`에서 기록된 한도를 읽습니다. 복사된 부모 이력은 제외합니다.
- Claude 입력에는 일반 입력과 캐시 생성·읽기를 합산합니다. 캐시도 현재 요청의 컨텍스트를 차지합니다. 이 구분은 [Claude의 사용량 필드 정의](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#tracking-cache-performance)를 따릅니다.
- Claude 한도는 로그의 명시적인 크기, 기록된 모델의 `[1m]` 태그, 지원하는 모델의 문서상 기본값 순으로 판단합니다. 기본값을 사용한 경우 Inspect에 `model default; settings may override`라고 표시합니다. 실제 한도는 설정이나 제공자에 따라 다를 수 있습니다. [모델 및 컨텍스트 설정](https://code.claude.com/docs/en/model-config), [Claude 상태 표시줄의 컨텍스트 필드](https://code.claude.com/docs/en/statusline)를 참고하세요.
- 한도를 판단할 수 없으면 `~12.9k / ? ctx`로 표시하고 남은 비율을 계산하지 않습니다. 사용량이 없으면 `—`를 표시합니다. 압축 기록을 만나면 이전 사용량을 지우고 다음 요청의 사용량을 기다립니다.
- Inspect의 **`CONTEXT AT EVENT`**는 해당 이벤트 시점까지 기록된 값으로 고정됩니다. 새 요청이 실행되어도 과거 이벤트의 숫자는 바뀌지 않습니다. 도구 호출은 호출 시작 시점의 값이며, 상세에 사용량 기록 시각과 한도 근거를 함께 표시합니다. 당시 기록이 없으면 이후 값으로 채우지 않습니다.

JSON 스냅샷의 `token_usage`는 별도로 유지하는 누적 처리량이며 `context`와 의미가 다릅니다. 누적 처리량은 캐시 입력의 반복 처리도 포함하므로 현재 컨텍스트 한도보다 훨씬 클 수 있습니다.

## 데이터와 한계

로컬 파일을 읽기 전용으로 엽니다. 네트워크 요청, 로그 업로드, 에이전트 실행·중지, 설정 수정 기능은 없습니다. `Space`는 화면만 멈추고 원래 에이전트는 계속 실행합니다.

내부 로그 형식은 버전에 따라 달라질 수 있습니다. 지원하지 않는 레코드는 건너뛰고, 잘못된 JSON과 8 MiB를 넘는 레코드는 개수로 표시합니다. 아직 줄바꿈이 기록되지 않은 마지막 줄은 완성될 때까지 기다립니다. 파일 교체와 길이 감소 시 다시 읽습니다. 암호화되거나 숨겨진 추론은 표시하지 않습니다. 로그에 기록되지 않은 내부 호출이나 서브 에이전트 결과를 복원할 수는 없습니다. `codex exec --json` stdout 이벤트 스트림, 원격 세션, Claude 웹 채팅은 별도 입력 형식이므로 이 버전의 자동 수집 대상이 아닙니다.

한 이벤트의 입력/결과 표시는 각각 64 KiB로 제한하며 잘린 내용에 표시를 붙입니다. 전체 내용은 상세 패널에 표시된 원본 로그에 있습니다. 출력의 ANSI 제어 문자는 제거하지만, 로그 자체에 담긴 비밀값은 마스킹하지 않습니다. 화면 공유나 JSON 내보내기에는 실제 대화·도구 출력이 포함될 수 있습니다.

비대화형 확인:

```sh
agent-flow --demo --render 160x42  # Dashboard 텍스트 화면
agent-flow --demo --flow --render 160x42  # Flow 텍스트 화면
agent-flow --snapshot             # 현재 수집 범위의 JSON; 대화 내용 포함
```

로그 저장 구조 참고: [Claude Code 디렉터리 문서](https://code.claude.com/docs/en/claude-directory), [Codex App Server의 스레드와 로컬 기록](https://learn.chatgpt.com/docs/app-server). 파서의 구체적인 필드 지원은 실제 로컬 로그와 합성 테스트를 기준으로 검증했습니다.

## 개발과 검증

```sh
cargo fmt --check
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --release
python3 scripts/smoke_tui.py target/release/agent-flow
```

`parser.rs`가 제공자별 로그를 `model.rs`의 공통 이벤트로 변환합니다. `source.rs`는 파일 발견과 증분 읽기, `timing.rs`는 보관된 이벤트의 시간 분석, `dashboard.rs`는 순위와 턴 선택, `parallel.rs`는 가족 관계와 독립된 이벤트 열, `app.rs`는 탐색·필터, `ui.rs`는 반응형 TUI를 담당합니다. 테스트는 호출 결과 연결, 부모 이력 제외, 파일 추적, 보존 한도, 상태, 시간 계산의 중복·누락, 열별 Follow·선택 유지, 검색·탐색과 화면 크기 변경을 검증합니다. 데모 데이터에는 실제 사용자 로그가 포함되지 않습니다.
